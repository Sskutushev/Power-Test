# Обзор за 10 минут

Короткий маршрут для того, кто открыл репозиторий и хочет понять уровень, не читая всё подряд.

## Запустить

```powershell
Copy-Item .env.example .env         # впишите WEATHERAPI_CREDENTIAL
docker compose up --build -d
start http://localhost:8080
```

Одна команда прогоняет весь набор проверок, которым руководствуется CI:

```powershell
./scripts/verify.ps1                # или ./scripts/verify.sh
```

Формат, сборка без единого warning, 138 тестов, скан уязвимых зависимостей, сборка образа и проверка,
что в нём нет ни root-пользователя, ни credential.

## Что стоит потыкать в интерфейсе

| Действие | Что демонстрирует |
|---|---|
| Просто открыть | Интро-экран — это и есть честное состояние загрузки, а не декорация поверх спиннера |
| Строка под температурой | Выводы, а не показатели: когда пойдёт дождь, почему ощущается холоднее, как одеться |
| График на 48 часов | Ночь залита, осадки столбиками, пунктир — «сейчас». Inline SVG, без графических библиотек |
| Провести мышью по ленте часов | Детали часа обновляются без единого запроса на сервер |
| Потянуть ленту мышью | Drag-to-scroll; вертикальное колесо листает её горизонтально |
| Нажать на день в списке трёх дней | Раскрываются часы дня, восход, закат, длина светового дня, фаза луны |
| Навести на карту и покрутить колесо | Зум активируется только под курсором, чтобы не перехватывать скролл страницы |
| Переключить темы | Четыре темы, выбор переживает перезагрузку, применяется до первой отрисовки |
| Выключить сеть в DevTools и обновить | Service worker отдаёт офлайн-страницу с последним сохранённым прогнозом |
| Установить приложение | Чип «Установить» появляется, только когда браузер действительно готов установить |

## Что стоит открыть в коде

**`src/Weather.Application/Weather/GetWeatherDashboard/HourlyForecastSelector.cs`** — ядро ТЗ.
Чистая функция без доступа к системным часам; «сейчас» приходит из ответа провайдера. Тесты рядом
проверяют инвариант на всех 24 часах и границу суток.

**`src/Weather.Application/Weather/GetWeatherDashboard/WeatherAdvisor.cs`** — превращение данных в
ответы. Тоже чистая функция, 20 тестов на правила.

**`src/Weather.Infrastructure/WeatherApi/ProviderFailureMapper.cs`** — одно место, где транспортные и
Polly-исключения превращаются в закрытую таксономию. Ни одно нетипизированное исключение не доходит до UI.

**`src/Weather.Infrastructure/DependencyInjection.cs`** — почему таймауты живут в resilience-пайплайне,
а не в `HttpClient.Timeout`, и почему 401/429 не ретраятся.

**`tests/Weather.Architecture.Tests/ArchitectureRulesTests.cs`** — двенадцать правил, которые ломают
сборку: направления зависимостей, непубличность DTO провайдера, запрет системных часов в бизнес-логике,
отсутствие credential в конфигах.

## Три бага, которые нашли тесты, а не глаза

1. **`pressure_mb` приходит дробным** (`1013.0`). Привязка к `Int32` проходила на всех рукописных
   фикстурах и падала на живом API. Найдено вызовом настоящего провайдера, закрыто contract-тестом на
   live-shaped фикстуре — [ADR-002](decisions/ADR-002-weather-provider.md).
2. **Blazor печатал литерал вместо сообщения.** `Message="failed.Message"` — это строка, а не выражение.
   На экране пользователя стояло `failed.Message`.
3. **Почасовая лента растягивала документ** на мобильном: grid-элементы по умолчанию `min-width: auto`.
   Поймано E2E-проверкой `document.scrollWidth <= clientWidth`.

## На что смотреть под капотом

- **Prerender выключен осознанно** — иначе `OnInitializedAsync` выполняется дважды и каждое открытие
  страницы стоит двух вызовов платного API. Зафиксировано component-тестом
  «одно открытие = один запрос» и [ADR-003](decisions/ADR-003-server-rendering.md).
- **Stampede** — 50 одновременных читателей на холодном кэше дают ровно один вызов провайдера
  (integration-тест).
- **Readiness не ходит в провайдера** — оркестратор опрашивает его каждые несколько секунд; проба,
  которая дёргала бы WeatherAPI, сожгла бы квоту и привязала бы нашу доступность к чужой.
- **CSP без `unsafe-inline` и `unsafe-eval`** — поэтому Leaflet вендорится локально, а бутстрап темы
  вынесен в модуль. E2E проверяет, что приложение не нарушает собственную политику.
- **Контейнер** — non-root, `cap_drop: ALL`, read-only корневая ФС; ключи DataProtection на томе,
  что и делает read-only возможным.

## Осознанные отказы

Ни SQL, ни очередей, ни Hangfire, ни микросервисов — при том что они есть в описании вакансии.
Обоснование каждого отказа в разделе Trade-offs в [README](../README.md). Планировщик показан
единственным уместным способом: выключенным по умолчанию `BackgroundService` для прогрева кэша.
